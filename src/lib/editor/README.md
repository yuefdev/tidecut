# Timeline and media runtime

`timeline-engine.ts` is the source of truth for preview, editing, save/recovery and
render graph generation. Its internal time unit is seconds. `serializeProjectState`
adds integer `startMs`, `durationMs` and `trimInMs` fields for the Rust/FFmpeg render
boundary while retaining seconds for a lossless editor round trip.

## Core timing rules

- Source time is `trimIn + localTimelineTime * speed`.
- A normal head trim keeps the clip's timeline out point fixed.
- A ripple head trim keeps the sequence gapless by shifting the clip body and all
  downstream clips by the inverse trim delta.
- A ripple tail trim and ripple delete shift only downstream clips on the edited
  track. Other tracks preserve sync unless a future explicit multi-track sync group
  requests otherwise.
- Locked tracks reject trim, split, speed and delete operations in the engine, not
  just in the UI.

## Preview and export parity

`buildFramePlan` resolves every active visual layer and audio source at one timeline
time. It applies track mute/solo, clip and track gain/pan, playback speed, keyframes
and transition envelopes. `CanvasCompositor` consumes visual layers and
`WebAudioMixer` consumes audio sources. The same frame plan can be adapted to an
offline renderer, avoiding a second set of timeline rules in export code.

Visual layers are returned in track-array order: later entries composite over
earlier entries. Audio sources are independent mixer strips, so overlapping clips
are mixed rather than replaced.

## Timeline component API

- `getProjectState()` returns the JSON-safe millisecond render/save contract.
- `loadProjectState(state)` accepts the current snapshot or the second-based editor
  state and resets undo history.
- `getFramePlan(time)` returns compositor and mixer decisions for the requested
  timeline time.
- `setClipWaveform(id, peaks)` hydrates cached/proxy waveform peaks.
- `onProjectStateChange` publishes a complete snapshot after edits.

Waveform decoding is best-effort in the browser for standalone audio codecs. Video
container waveforms should be generated by the proxy/cache pipeline and injected
through `setClipWaveform`, because browser `decodeAudioData` support for MP4/MOV
audio tracks varies by platform.
